# Digital Product Launch (whole-project skill)

One repo → five coordinated deliverables plus the doc that ties them together:

1. **Sales site** — static HTML/CSS/JS, every paid CTA hard-links the checkout URL.
2. **Paid ebook PDF** — built locally with fpdf2; gitignored; uploaded to the
   marketplace by hand. Never deployed, never committed.
3. **Free sample PDF** — chapter 1 with a clickable CTA back to the sales page;
   committed and deployed. This is the only public taste of the product.
4. **Listing covers** — square marketplace images generated in code (Pillow).
5. **Video ads** — motion graphics rendered from the same brand (see `scripts/render_ad.py`).
6. **Listing doc** (`docs/<marketplace>-listing.md`) — source of truth: live links,
   product fields, copy, delivery-file workflow, publish checklist.

## When to use

- "Launch/sell this ebook or digital product."
- "Build the sales page / the PDF / the covers / the ads" for a product repo.
- Rebuilding any deliverable after a price, title, or copy change (everything is
  generated from code, so edits are re-runs, not redesigns).
- Auditing whether the paid asset is leaking into git or the deploy.

## Pipeline order (matters)

1. **Mine or define the brand first**: palette hexes, display+body fonts, tone rules,
   price + anchor price, guarantee, checkout URL, author. See `references/brand-and-copy.md`.
2. **Write the listing doc early** — it forces decisions (title, price, promise, audience)
   that every other artifact consumes.
3. **Build the ebook** (`references/ebook-pdf.md`) → paid PDF to an ignored dir + free sample.
4. **Build the site** (`references/sales-site.md`) around the free sample + checkout.
5. **Generate covers** (`references/listing-covers.md`) from the cover art.
6. **Cut ads** (`references/ads-motion.md`, `scripts/render_ad.py`) last — they remix 1–5.
7. **Publish** per `references/paywall-and-git.md`: commit free assets only; upload the
   paid PDF to the marketplace manually; deploy static site excluding ignored dirs.

## Non-negotiable conventions

- **Paid asset lives in an ignored directory** (this project: `delivery/`). Confirm with
  `git check-ignore -v <path>` before declaring success. The deploy must never serve it.
- **Every paid CTA carries an explicit `href` to checkout** in the HTML, so purchase works
  with JavaScript disabled; JS only re-wires `[data-buy]` buttons.
- **Free sample is the only public product file.** One public taste, everything else gated.
- **All imagery and PDFs are generated by committed scripts.** No hand-edited binaries:
  price/title changes are re-runs.
- **Price anchoring**: show compare-at price struck through next to launch price, and
  repeat the guarantee near every price.
- **Tone is no-hype**: state the work involved, forbid get-rich-quick framing, name who
  the product is NOT for. This is both ethics and conversion strategy here.

## Reusable scripts in this skill

- `scripts/render_ad.py` — config-driven motion-graphics ad renderer (3 aspect ratios,
  Pillow frames piped to ffmpeg, VO mux). Edit `CONFIG`, preview stills, then render.
- `scripts/ebook_skeleton.py` — minimal fpdf2 book builder with the proven helper set
  (cover, TOC, chapters, callouts, task boxes, references, numbered footer). Point it at
  your chapter data.
- `scripts/make_cover.py` — square marketplace-cover generator (kicker band, serif title
  block, price pill, art card, feature band, paper grain). Config-driven.

## Cross-cutting gotchas

- fpdf2 + DejaVu: `₦`, `✓`, `✗` render; colour emoji does not. Strip/replace emoji before
  drawing (keep a replacement table).
- Pillow `anchor="ma"` y is the ascender TOP — measure bboxes before placing rules/underlines.
- Always width-fit display type (`fit_font`); fixed sizes clip on narrow canvases/formats.
- Verify PDFs by parsing (`/Type /Page` count, `/Count`, `%%EOF`), not by trusting the build log.
- Ephemeral environments delete ignored dirs and venvs; re-verify outputs with `ls` right
  before reporting, and recreate the venv (`fpdf2`, `pillow`, `imageio-ffmpeg`).
- Marketplace/release upload hosts can be network-blocked in sandboxes; commit+push free
  assets and verify via the GitHub contents API instead of curl.
- Free sample PDF is tracked, so rebuilding it dirties the tree with timestamp/ID churn;
  that is expected — restore or commit deliberately.
