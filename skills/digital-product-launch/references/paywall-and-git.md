# Paywall & git conventions

The commercial heart of the project: the paid file must never reach git or the deploy.

## Directory contract

| Path | Tracked? | Deployed? | Why |
|---|---|---|---|
| `delivery/` (paid PDF, ad masters, VO stems) | NO — in `.gitignore` | NO | paid asset + heavy intermediates |
| `assets/ebook/free-sample-*.pdf` | YES | YES | the single public taste of the product |
| `assets/img/selar-cover*.png` | YES | YES (covers optional) | listing images, generated by script |
| `assets/img/opt/`, generated bands | NO — ignored | NO | render intermediates |
| `.venv/`, `__pycache__/`, `*.pyc` | NO | NO | environment |
| `scripts/` | YES | NO (excluded from upload) | reproducibility without exposing product |

Verify before claiming success:
```bash
git check-ignore -v delivery/<paid>.pdf     # must print the ignore rule, exit 0
git status --short                          # paid file must NOT appear
git ls-files | grep -c <paid-name>          # must be 0
```

## CTA / checkout contract

- `const BUY_URL = "<checkout>"` and `const WHATSAPP_NUMBER = "<digits>"` at the top of the
  site JS; `[data-buy]` buttons get re-wired from it.
- Independently of JS, every paid `<a>` has the checkout URL as a literal `href`.
- Canonical URL + Product structured-data URL = the live site URL, not the repo.

## Deploy contract (static host, e.g. Cloudflare Pages)

- No build step: framework preset None, empty build command, output dir `/`.
- Upload/connect excludes `.git`, `.venv`, `scripts`, and everything ignored — so the paid
  PDF cannot be published even by accident.
- Only the free sample is publicly reachable; test by requesting the paid path on the live
  host and expecting 404.

## Publish checklist (marketplace, e.g. Selar)

1. Rebuild paid PDF locally; confirm page count + size.
2. Upload paid PDF as the delivery file BY HAND (never via repo).
3. Upload primary square cover; keep alternates for later listing-image tests
   (do not attach all variants as product files).
4. Set price + compare-at price; product type = digital download.
5. Paste listing copy from the listing doc (short desc, full desc, who-it's-for,
   what-you-receive).
6. Update the listing doc's live links; commit the doc (it is safe: no paid asset inside).
7. Re-run the git verification block above.

## Sharing heavy/paid artifacts when a sandbox can't upload

- Release-asset upload hosts may be blocked; fall back to committing ONLY assets that are
  safe to publish (ad creatives) to a branch, then verify via the GitHub contents API.
- Never "solve" a sharing problem by committing the paid PDF. If a durable home for it is
  required, use the marketplace itself or private storage, not a public repo.
